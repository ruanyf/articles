# 腾讯云的新玩法，AI 变成 NPC，帮你写代码

## 一、

我曾经想过，未来游戏里面的 NPC（非玩家角色）一定是 AI，你可以跟它互动，甚至命令它帮你做任务。

![](https://cdn.beekka.com/blogimg/asset/202607/bg2026072501.webp)

我万万没想到，第一个实现这个想法的居然是腾讯云，但不是让 NPC 玩游戏，而是让 NPC 帮你写代码、做开发。

它推出了 AI 编码工具 CodyBuddy 的[一个全新升级](https://www.oschina.net/news/477664)，名字就叫 CodeBuddy NPC。

![](https://cdn.beekka.com/blogimg/asset/202607/bg2026072502.webp)

你登录它的平台，就可以指挥一群 NPC（即各种 AI 模型）帮你做任务。

![](https://cdn.beekka.com/blogimg/asset/202607/bg2026072503.webp)

上图就是你同时[唤起四个 NPC](https://cnb.cool/npc/CodeBuddy/-/issues/57)，给它们派任务，每个 NPC 做一遍，一共做四遍。

可以看到，每个 NPC 的名字后面，会附上本次任务消耗的 Token 和对应的费用，好像在提醒你别超标。

虽然官方不说自己借鉴了游戏的思路，只说这是**开发者的云端“AI 队友”**。但是我觉得，它本质就是一个云端的“开放世界”，你登录后进行“编码游戏”，允许任意调用 NPC。

而且，它是“云端游戏”，所有操作都在云端完成，跟本地机器和环境都无关。你完全可以跟 NPC 交待清楚以后，机器一关就离开，后面随便找台电脑，查看任务进展。

经过试用，我觉得这是目前最简单的 AI 开发方案。**不需要任何配置或安装，只需一个浏览器**，云端功能超完整。而且，**只要选择免费模型，还不花钱**。

## 二、

使用 CodeBuddy NPC 目前只能通过腾讯云的 [CNB 平台](https://cnb.cool/)。

![](https://cdn.beekka.com/blogimg/asset/202607/bg2026072504.webp)

CNB 平台是“云原生构建”（cloud native build）的缩写，但是你不要管它的名字，它其实就是腾讯云的 GitHub 替代品，用作代码托管平台。

![](https://cdn.beekka.com/blogimg/asset/202607/bg2026072505.webp)

上面就是它的[仓库主页](https://cnb.cool/yifeng.ruan/codebuddy-test-webpage)，是不是看上去跟 GitHub 一模一样。

据说腾讯内部就用这个平台管理代码，现在开放了，做了一个公开版本给外部使用。

它以前可能没有 GitHub 那样强大，但是现在多了 CodeBuddy NPC，我觉得至少在 AI 方面比 GitHub 好用。大家看了后面的例子，就会知道我没夸张。

**CodeBuddy NPC 相当于允许你用自然语言，操作底层代码平台的所有功能**：提交代码、管理 Issue、合并 PR、持续构建等等。它会完全改变你使用代码平台的方式。

## 三、

CodyBuddy NPC 使用自然语言唤起 NPC，需要有一个输入提示词的地方，当前仓库的 issue 就是天然的操作入口。

下面是最简单的 Hello World 示例。你先在网页创建一个空的仓库，然后进入该仓库，打开一个新的 issue，写下你的意图，比如“新建一个介绍北京旅游的网站”。

![](https://cdn.beekka.com/blogimg/asset/202607/bg2026072601.webp)

然后，你指派一个 NPC 去完成这个任务。

系统内置多种 NPC（AI 模型），只要输入符号`@`，就会有一个弹出窗口，列出可供选择的 NPC。

![](https://cdn.beekka.com/blogimg/asset/202607/bg2026072602.webp)

上图中，可以看到官方的编程助手 `CodyBuddy`，目前可以免费使用。

另外，官方还提供一个`npc/CodeBuddy`的群组，里面有各种国产模型可供选择。

![](https://cdn.beekka.com/blogimg/asset/202607/bg2026072603.webp)

其中，腾讯的 Hy3 是免费使用，其他都附上了费率。我们就选择免费的 Hy3。

选好 NPC 以后，就可以提交 issue 了。NPC 会自动运行，生成结果后，就在当前 issue 创建一个回复，加以说明。

![](https://cdn.beekka.com/blogimg/asset/202607/bg2026072605.webp)

上图划线处是本次 NPC 消耗的 Token 和费用。点击进去，就会看到 NPC 的详细日志。

![](https://cdn.beekka.com/blogimg/asset/202607/bg2026072606.webp)

这时，[生成的代码文件](https://cnb.cool/yifeng.ruan/codebuddy-test-webpage)已经自动提交到仓库了。

![](https://cdn.beekka.com/blogimg/asset/202607/bg2026072607.webp)

整个过程只需要新建一个 issue，接下来的事情都会自动帮你搞好。如果有需要，还能生成发布脚本，帮你发布，是不是简单到不能再简单了？更别说这一切还免费。

## 五、

CodeBuddy NPC 可以做的事情非常多，基本上，你在 GitHub 的常用操作，都可以让 NPC 去做。

发布 issue 的时候，菜单栏有一个“替我上班”开关。

![](https://cdn.beekka.com/blogimg/asset/202607/bg2026072614.webp)

关闭这个开关，生成结果将自动生成 PR（下图），需要手动批准合并。

![](https://cdn.beekka.com/blogimg/asset/202607/bg2026072615.webp)

上图就是 AI 生成的 issue 回复，因为没有权限，它提示已经提交为 PR，并给出了 PR 和预览的链接。

**（2）代码冲突**

提交 PR 后，有可能出现代码冲突。你可以直接让 NPC 去解决（下图）。

## 六、

我已经用了两天，觉得 CodyBuddy NPC 很有创意，将 AI 当作 NPC 使用，还蛮贴切。确实很像开发者的一个虚拟队友，从辅助工具的角色到独立承担研发任务。

更重要的是，**它与代码托管平台 CNB 深度结合，将开发自动化提高到一个全新的层次**。GitHub 的主要功能，几乎都可以用自然语言唤起 NPC 完成，比如开发、Git 操作、issue、PR、CI\CD 等等。

CodyBuddy NPC 自动把当前仓库当作上下文，提交在模型，在独立的沙箱环境中运行，最大程度方便开发者。根据官方文档，系统内置了 Token 优化工具，会尽量压缩仓库的上下文，控制 Token 消耗。

大家可以去玩玩这个最新形态的“云端游戏”，尝尝使唤 NPC 的感觉。

让 AI 直接融入企业现有研发流程，成为研发流程里的“AI 原住民”。开发者只需下达目标，NPC 即可自主获取上下文、闭环完成任务并交付可验收成果。

此次腾讯云CodeBuddy 的升级覆盖多个维度：在能力上，NPC 打通了从需求到交付的关键链路；在成本上，CodeBuddy NPC官方首轮 Token 消耗已从2 万 + 优化到当前约 2 千，成本降低超过90%；在底层上，CodeBuddy NPC深度融入腾讯云原生构建 CNB 平台，实现可规模化、可治理、可持续的工程化落地。

目前，腾讯云 CodeBuddy NPC 已与腾讯云研发协作平台 TAPD 打通，开发者可通过 cnb.cool 进行体验。

## 产品简介

以“让AI住进企业已成熟工作流”为思路，CodeBuddy NPC以Git仓库为AI原生记忆，让 AI 直接融入企业现有研发流程，成为流程里的“AI 原住民”。当行业普遍困于“卷速度”之时，腾讯云关注全链路研发流程层，解决AI 与研发流程割裂，这一困扰企业已久的问题。

CodeBuddy NPC的发布实现了AI编程工具从“单点效率工具”向“工程化协作者”升级，进而围绕 AI 重构软件工程协作方式，定义“AI 原生团队”。

（1）让 AI 有记忆：从辅助写代码，到能独立交付结果

过去Vibe Coding模式下，开发者面临的问题不在于AI不够聪明，而在于它“没有研发流程的记忆”——它不在团队的代码仓库里、不接团队的构建和验证流程，成了一个游离在流程之外的旁观者。

洞察到企业核心痛点并非编码速度不足，而是 AI 与研发流程割裂，腾讯云跳出单点工具，关注全链路研发流程层，以“让AI住进企业已成熟工作流”为思路，让AI住进研发流程，Git仓库作为原生记忆，打造CodeBuddy NPC。在这一升级下，开发者的角色便从“代码的生产者”变为“定目标、做决策、验收成果的监督者”，从根本上重构人与AI在研发中的协作关系。

功能上，CodeBuddy NPC能够独立闭环完成研发任务，自主完成从任务承接、规划、执行、验证到自动迭代优化的全过程，直至交付最终结果。开发者的角色便从“生产者”转变为“监督者”和“规则制定者”。

在此基础上，CodeBuddy NPC能进一步融入团队协作场景。企业无需改造现有工作流即可快速完成部署，针对线上缺陷修复、新功能开发等高频业务场景，CodeBuddy NPC 能把“需求接收—实现—验证—合并”的链路压缩成更短闭环，原本需要大量人力在多工具间搬运上下文和反复确认的流程，被收敛为“AI 执行、人工决策”的协作方式。

更进一步，CodeBuddy NPC还支持多角色NPC工程化协作。通过Role（角色定义）、SOP（标准流程）、Skill（技能配置）、Team（团队编排）四个维度，企业可定制专属的NPC团队——产品NPC、技术Leader NPC、开发NPC、测试NPC各自认领任务、并行推进、自动联调，完成复杂功能迭代的全链路交付。

（2）Token 消耗首轮降低超90% 

CodeBuddy NPC是业内首个提出并落地了“AI Native Git”技术范式。让Git仓库成为AI的原生记忆，AI直接入驻团队已有的Git、Docker、CI/CD和质量门禁，复用现有流水线，形成“提交→验证→修复→再验证”的自动闭环，真正实现从提速到融入的飞跃。

这背后是腾讯云CNB平台超过八年的技术积淀。CNB平台自2018年起在腾讯内部持续迭代，积累了包括Git代码托管、CI/CD流水线、制品库与云原生开发环境四大能力，支撑腾讯文档、腾讯广告、手机QQ等高频迭代业务，应对伴随模型文件引入后，百G乃至TB级超大仓库。目前，腾讯云CNB平台每月服务超过10万名开发者，覆盖物流、消费电子、零售、金融等多个行业大型企业与业务场景。同时，CNB为国内开发者提供了自主可控、数据合规的研发协作环境。

此外，腾讯云还沉淀出了一套 Agent 能效优化方法论。具体来看，这套方法论包含四个方向：做减法——裁剪冗余工具、精简描述、消除二义性；立规矩——把 SOP 写进提示词，让模型少走弯路、减少自行试错；提效率——CLI 紧凑输出、Cache 去重叠、降低工具调用轮次；标准化——对 Skill、CLI、系统工具持续调优。

Agent 执行一次任务往往需要多轮 LLM 调用，而每一轮都会把系统提示词、工具描述和上下文重新发给模型。系统提示词是每轮都要"带着走"的固定成本：首轮压得越小，后续每一轮都跟着省，形成贯穿整个对话周期的"滚雪球"式节约。凭借上述优化，腾讯云官方提供的 CodeBuddy NPC 首轮 Token 消耗已从早期的 2 万 + 降至当前的 2 千左右，降幅超过 90%，极大降低了多轮任务的成本基数。

在此之上，开发者还能自定义 NPC 的模型调用策略：简单任务交给成本较低的模型（如 DeepSeek），复杂任务调用能力更强的模型（如 GLM）；面向多模态研发任务（如游戏开发中的配音、生图等），可借助 CNB 提供的容器沙箱 + 开源模型扩展能力上限。协作团队也能根据任务特点自主配置，在质量与成本之间取得平衡。 

（3）腾讯云一以贯之的技术理念：让AI融入真实工作流

腾讯云CodeBuddy NPC的推出，标志着AI编程工具从“单点效率工具”向“工程化协作者”的演进。当AI成为研发流程的“原住民”， 开发者个人便从重复编码、流程调试的琐事中抽离，聚焦业务创新与关键决策，团队也能打破人力协作的流程壁垒，依托多角色NPC实现全链路自主协同。

腾讯云 CodeBuddy、CNB 产品负责人黄友昆表示，腾讯的实践不是把 AI 工具“分发给每个人”就结束，而是围绕 AI 重构协作方式：PM 通过需求录入 Skill 发起任务，AI 参与需求澄清与任务拆解；技术 Leader 与 AI 共建技术方案并生成研发任务；研发与 AI 协同完成开发验证；交付分析 Skill 回收全过程数据，反哺下一轮流程优化。这个闭环，定义了腾讯所理解的“AI 原生团队”。

这套理念在腾讯云系列产品演进中保持了一致性：CodeBuddy 让 AI 深入开发一线，形成了从插件到 IDE、CLI 的多形态能力，并在腾讯内部形成大规模应用；2026 年 3 月 ，由 CodeBuddy 团队打造的 WorkBuddy 上线，把同一理念扩展到全场景办公提效；而本次发布的 CodeBuddy NPC，则进一步围绕 Harness（云端智能体运行时治理层）升级，把“AI队友”能力落在研发流程核心地带。

“我们并不希望行业再多一个“更会写代码”的工具，而是希望企业真正拥有一个能理解研发上下文、遵守团队流程、持续交付结果的 AI 队友。从 CodeBuddy 到 WorkBuddy，再到 NPC，变的是场景，不变的是‘让 AI 融入真实工作流’的技术理念。”

## 特点

（1）云端，异步操作，不绑定机器。

（2）Git 融合。

（3）完整流程。NPC已开始接管相对完整的局部任务，例如：独立开发网站、自主解决合并冲突、自动修复CI问题。这意味着NPC能够独立闭环完成一项任务。所谓“闭环”，是指AI能够自主完成从任务承接、规划、执行、验证到自动迭代优化的全过程，直至交付最终结果——接收需求后，NPC可以自动读取项目代码、规划方案，完成编码、提交 PR 并生成预览环境；过程中可自主解决合并冲突；构建失败时自动接手CI修复，读取日志、迭代修复，直至门禁通过，全程无需人工介入。任务规模可大可小，但闭环的完整性不变。在这一阶段，人的角色从“生产者”转变为“监督者”和“规则制定者”。

· CodeBuddy NPC（2026年7月上线）：进一步围绕 Harness（云端智能体运行时治理层）升级，把“AI队友”能力落在研发流程核心地带。

变的是场景，不变的是技术理念。腾讯的实践不是把 AI 工具“分发给每个人”，而是围绕 AI 重构协作方式：通过多角色 NPC 协同，形成需求澄清、方案共建、开发验证到数据回流的闭环，也由此定义了腾讯所理解的“AI 原生团队”。
