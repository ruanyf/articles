# IDE 已死吗？从 TRAE 双端合一谈起

## 一、TraeCode 与 TraeWork 合并

我看到一个最新消息：TraeWork 与 TraeCode 合并了，升级为新的 [TRAE](https://www.trae.cn/) 客户端。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100605.webp)

这让我很惊讶，因为 TraeWork 本来就是从 TRAE IDE 中分离出来的，印象中就是几个月前，没想到这么快又升级了。

但是，转念一想，这也正常。IDE 的产品形态，在 AI 时代，早已变得不确定，快速变化才是常态。

## 二、AI 时代的 IDE

大家是否意识到了，**（传统的）IDE 可能已经死了。** 这是最近几个月，我一直在想的问题。

手工编码才需要 IDE，可是未来都是 AI 编码，你完全可以不碰代码就做出软件。那样的话，IDE 就不是必需的了。

AI 时代需要不一样的开发工具，有人给这种全新的开发工具起了一个名字，叫做 ADE，即作为 AI 代理的集成开发环境（Agentic Development Environment）。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100606.webp)

问题是，目前没人知道 ADE 长什么样子——应该拥有怎样的界面，具备哪些功能——大家都在摸索。

正好借着这次 TRAE 的升级，我来说说我对 AI 时代开发工具的想象，什么样的软件才符合未来的开发需要。

## 三、TRAE 的产品形态变化

TRAE 是国内第一个专门用于 AI 编程的 IDE。

它最早的产品形态，接近于传统的 IDE，就是代码文件编辑窗口 + AI 辅助功能，比如代码生成和代码解释。

事实上，当初的样子一直保留到现在，只是名字改成了 IDE 模式（下图）。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100804.png)

上图就是现在版本的 IDE 模式，看上去跟传统 IDE（比如 VS Code）很像，只是右侧多了一个 AI 对话面板。

我认为，这是 **ADE 的第一种形态：AI 增强版的传统 IDE**。它依然注重代码管理，适合那些还需要人工阅读和编辑代码的程序员。

后来，AI 模型变得越来越强，这个形态就显出它的局限了。

> （1）AI 除了写代码，还可以生成 PRD、设计稿、测试、文档等等。
>
>（2）AI 可以分解任务，生成多个子任务，同时新建多个实例按顺序完成这些子任务。
>
>（3）多个 AI 代理，可以并行处理多个代码仓库。

以上这些能力，都很难做进传统的 IDE 界面，需要 IDE 做出变革，改变纯代码编辑的界面，容纳更多的功能。

这时，TRAE 就新增了 SOLO 模式（下图），增加了一个全新界面，是最早支持 AI agent 编程的国产开发工具之一。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100805.png)

可以看到，SOLO 模式默认没有代码编辑器，左边栏是一个任务列表。AI 会自动根据所执行的步骤，在右边面板打开相应的工具。

我把它称为 **ADE 的第二种形态：任务执行器形态**。它以任务为中心，聚焦于完成任务，不再突出代码功能，编辑器只是它内置的一种工具而已。

到这时为止，开发工具居然专注于 Coding，还是属于代码工具。对 TRAE 来说，作为国内领先的代码工具，它已经积累了庞大的用户基础，但是这些用户都属于程序员。它还没有想到，IDE 也可以有非程序员的用户。

## 四、Agent 模式

从今年年初开始，AI 进入了一个全新阶段：能够操作外部工具，完成各种任务。比如，操作外卖软件下单奶茶，或者操作飞书发送消息。

一时间，各种 AI 助手纷纷问世。IDE 自然也要顺应潮流，开始向工具助手转型。

TraeWork 就是在这种背景下推出的，它的定位是一个办公助手，面向普通用户，自动调用各种工具完成办公任务。

虽然，TraeWork 现在已经合并进了 TRAE，但是界面和基本功能没怎么变，只是名字改成了“Agent 模式”（代理模式）。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100806.png)

上图就是 TRAE 最新版的“Agent 模式”的样子，很像以前 TraeWork 的界面。你可以把它看成一个工作助手，可以加载各种能力，连接各种外部工具，帮助你完成工作。

我认为，这是 **ADE 的第三种形态：工具连接中心形态**。它管理各种能力和外部工具，根据需要自动调用它们。

## 五、双端合一

任务执行器形态和工具连接中心形态，虽然都能接受指令，完成任务，但是它们的使用目的和服务对象其实不太一样。

所以，TraeCode 和 TraeWork 一开始是分成两个客户端，面向不同的用户：前者面向开发者，后者面向办公用户。

现在，这两个客户端合并了，双端合一，反应了**开发工具的大趋势：淡化代码色彩，向通用工具转变，服务更广大的用户群体**。

现在，新版的 TRAE 是一个客户端，但包含两种模式：IDE 模式和 Agent 模式，在右上角切换（下图）。IDE 模式内部又可以切换到 SOLO 模式。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100703.webp)

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100704.webp)

两种模式的分工也很明确。

> **IDE 模式**：聚焦单项目的代码编辑，其中的 SOLO 模式更侧重单项目的 AI 全流程辅助开发。
>
> **Agent 模式**：全局工作台，一个窗口管理多项目、多 Agent、多工具，"从想法到结果"的全流程管理。

简单说，就是一句话。**IDE 模式的重点是代码，程序员使用；Agent 模式的重点是任务和工作助手，不懂代码的小白用户也可以使用**。

## 六、面向未来的开发工具的特征

TRAE 作为国内最早的 AI Coding 专用工具，它的发展历程凸显了 AI 时代开发工具的思路演变。

我认为，从 TRAE 身上可以看到未来的开发工具的几个特征。

（1）**全链路开发平台**

AI Coding 上游和下游的每个环节，它都涉及，整个开发链路可以都用它完成。

需求拆解、方案生成、页面生成、 Demo 落地……它都可以做到，一个工具完成文档、设计、代码、测试，相当于开发闭环了。

（2）**多端实时同步**

提供桌面、网页、移动端三个客户端，可以实时同步，方便随时随地开发。

（3）**统一工作台**

一个工作台统一管理所有项目，调度多个 Agent 并行处理任务，跨项目推进，进度一目了然，需要深度修改时一键切换回 IDE 模式。

举例来说，TRAE 有一个“我的产物”页面（下图），各种项目产生的网页、幻灯片、文档、表格、视频、图片等，都可以在这个页面统一管理，不管产物是在本机还在云端。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100707.webp)

（4）**能力扩展接口**

提供各种能力扩展渠道，并能连接外部服务或数据。比如，TRAE 就有插件市场，可以加载技能、MCP 和外部服务。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100705.webp)

对于即时通讯软件，它提供“我的助理”功能，连接后只要“@Trae”，就能远程调用 AI。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100706.webp)

另外，它还提供模板库。文档模板和自动化任务模板，都可以直接套用。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100708.webp)

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100709.webp)

## 七、总结

我认为，传统的 IDE 应该是走到头了。随着 AI 通用能力的发展，**开发工具的代码色彩会越来越淡，开始向通用的任务管理工具转变**。

从 TRAE 就可以看出这种迹象，它的桌面版还区分 Code 和 Work 两种模式，而移动版已经不区分了，不管什么样的任务，都只有一个入口。

开发工具的目标用户也将大变。

专业开发者依然可以用它来开发提效，小团队和个人则把它用来“全链路开发”，以前的很多“领域工具”都将被它替代：项目管理、设计、测试、运营、文档、PPT 等等。

更重要的是，许多普通人也会开始使用它，他们不懂代码，但懂业务和产品，希望开发出自己需要的工具。开发工具将用内置的 AI Agent，帮助他们无码开发，做出 Demo，做到以前必须借助程序员才能做到的事情。

（完）

## 介绍

文章可通过场景化开发流程演绎，自然带出双模式切换以及新增功能点。

1. 一端拥有Agent与IDE双模式，覆盖全链路开发每一环
Agent 模式是 TraeCode 新增的开发模式：它让你在一个窗口内管理所有项目、调度多个 Agent，把开发从「让一个 Agent 帮我写代码」，升级为「指挥多个 Agent 一起从想法开始到交付结果」。加上Agent模式后，TraeCode一共具有两个开发模式：
- Agent 模式：适合以 Agent 为中心的全局工作台，所有项目和 Agent 任务在统一工作台中调度，从需求到编码的一站式 Agent 协助。
- IDE 模式：保留之前双模式，其中SOLO 模式适合单项目的 AI 端到端辅助开发，IDE 模式则适合聚焦单项目的深度代码编辑。

2. 新增自动化、模板库、我的助理功能，让开发更加优质高效
围绕 Agent 模式，TraeCode 同步上线自动化、模板库和我的助理。自动化任务把重复流程交给 Agent 持续执行，比如定时整理进度、跑固定检查；模板库适合快速启动常见开发场景，让产品方案、页面搭建、数据分析、技术文档不必每次从零开始；我的助理则把文档、汇报、协同这些非编码环节接进来，让开发过程里的沟通和交付更加无损。

3. 文档、设计、代码等产物统一管理，开发全流程清晰可控
Agent 模式支持在同一个界面里管理多任务。Agent 生成的代码变更、HTML 报告、PPT、Word 文档、图片、视频等内容，都会统一进入「项目产物」。开发者不用再从聊天记录里翻结果，也不用担心产物散在不同地方；每一次调研、设计、编码和测试，都会沉淀成可回看、可展示、可继续交付的成果。

4. 桌面、网页端、移动端同步升级，开发随时随地
这次升级会覆盖桌面端、网页端和移动端，移动端也会去掉 Work / Code的模式区分，轻松开启任务下发。无论你是在电脑前推进项目，还是离开电脑后继续查看 Agent 任务进度，TraeCode 都会把多端任务、项目产物和开发流程接到同一个工作台里，让任务不因为设备切换而中断。

## IDE vs ADE

IDE指“集成开发环境”，由人提供动力，消耗头发与脑细胞，典型的有VSCode、IntelliJ IDEA、Neovim等。

Code Agent是指利用AI生成代码的工具，由大模型提供动力，消耗代币和电力，典型的有Claude Code、Codex、OpenCode等，下文简称为Agent。

ADE 指“Agent 驱动开发环境”，

IDE搭配AI对话框，就像在牛车马车上安装一个发动机，
