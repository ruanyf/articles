# IDE 真的会被 AI 取代吗？从 TRAE 双端合一谈起

## 一、TraeCode 与 TraeWork 合并

昨天，我突然看到一个消息：TraeWork 与 TraeCode 合并了，升级为新的 TRAE 客户端。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100605.webp)

这让我很惊讶，因为 TraeWork 本来就是从 TRAE IDE 中分离出来的，印象中就是几个月前，没想到产品形态这么快又升级了。

但是，转念一想，AI 编程需要什么样的 IDE，本来就没有答案，快速变化才是常态。

## 二、AI 时代的 IDE

最近几个月，我一直在想这个问题，也想听听大家的意见：**传统 IDE 是否已经死了？**

手工编码才需要传统 IDE，可是未来都是 AI 编码，你可能都不必直接阅读和编辑代码。那样的话，IDE 不就没用了吗。

AI 时代需要不一样的 IDE，有人把这种为 AI 编程服务的 IDE 称为 ADE。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100606.webp)

但是，目前没人知道 ADE 应该什么样，拥有怎样的界面，具备哪些功能，大家都在摸索。

我对 TRAE 比较了解，它刚发布的时候，我就是它的内测用户。我就用它这次升级作为例子，谈谈我心目中 AI 时代的编程工具。

## 三、TRAE 的产品形态变化

TRAE 是国内第一个专门用于 AI 编程的 IDE。

那时，它的产品形态跟传统 IDE 还比较接近，就是代码文件编辑窗口 + 一些 AI 辅助功能，比如代码生成、代码解释等等。

事实上，当初的样子现在还能看到，只是名字改成了 IDE 模式（下图）。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100607.webp)

上图就是它现在版本的 IDE 模式，跟传统 IDE（比如 VS Code）看上去很像，但是多了 AI 对话窗口。

我认为，这是 **ADE 的第一种形态：AI 增强版的传统 IDE，注重代码管理**。它适合那些还需要人工阅读和编辑代码的程序员。

后来，AI 模型越来越强，这个形态就不太够用了。（1）AI 除了写代码，还可以生成 PRD、设计稿、测试、文档等等；（2）AI 可以分解任务，生成多个子任务，同时新建多个实例按顺序完成；（3）不同的 AI 模型，可以并行处理多个代码仓库。

以上这些能力，都需要 IDE 做出变革，扩展传统的代码模式，容纳更多的功能。

TRAE 后来推出的 SOLO 模式（下图），就是这种考虑。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100701.webp)

可以看到，SOLO 模式默认没有代码编辑器，左边栏是一个任务列表。它根据 AI 执行步骤的需要，自动打开所需的工具窗口。

这是 **ADE 的第二种形态：一个任务执行器，不再强调代码**，编辑器只是它附带的一种工具。

## 四、Agent 模式

从今年年初开始，AI 发展到一个全新阶段：能够操作外部工具，完成各种任务。比如，操作外卖软件下单奶茶，或者操作飞书发送消息。

于是，各种 AI 助手纷纷亮相。IDE 开发者也在思考：既然开发工具已经转向了任务导向，是否可以把用户扩展到非程序员，反正已经不强调代码了。

TraeWork 就是在这种背景下推出的，它的定位是一个办公助手，面向普通用户，使用各种工具完成办公任务。

现在，它作为“Agent 模式”，又重新合并进了 TRAE，但是界面和基本功能没怎么变。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100702.webp)

上图就是 TRAE 最新版的“Agent 模式”，也就是以前的 TraeWork。它是一个工作助手，更强调能力扩展，可以连接各种外部工具完成任务。

这是 **ADE 的第三种形态：一个工具连接中心，可以自动管理和调用各种能力和外部工具**。

## 五、双端合一

TraeCode 和 TraeWork 本来是两个客户端，面向不同的用户：前者面向开发者，后者面向办公用户。

现在，这两个客户端合并了，代表了**开发工具的一个趋势：淡化代码色彩，面向更广大用户群体**。

现在，新版的 TRAE 是一个软件包含两种模式：IDE模式和 Agent 模式，在右上角切换（下图）。 IDE 模式内部又可以切换到 SOLO 模式。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100703.webp)

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100704.webp)

这两种模式的分工也很明确。

> **IDE 模式**：聚焦单项目的代码编辑，其中的 SOLO 模式更侧重单项目的 AI 全流程辅助开发。
>
> **Agent 模式**：全局工作台，一个窗口管理多项目、多 Agent、多工具，"从想法到结果"的全流程管理。

由于 Agent 模式的重点是任务和工作助手，不是代码，所以小白用户现在也可以使用它了。

## 六、面向未来的开发工具的特征

TRAE 作为国内最早的 AI Coding 专用工具，长期专注于这个领域，它的发展历程就代表了 AI 开发工具的思路演变。

我认为，未来的开发工具需要做到以下几点，这也是 TRAE 正在做的事情。

（1）**全链路开发平台**

AI Coding 的上游和下游都涉及，整个开发链路可以都用它完成。

从需求拆解、方案生成、页面生成到 Demo 落地，它都可以做，一个工具完成文档、设计、代码、测试，相当于闭环了。

（2）**多端实时同步**

提供桌面、网页、移动端三个客户端，可以实时同步，方便随时随地开发。

（3）**统一工作台**

一个工作台统一管理所有项目，调度多个 Agent 并行处理任务，跨项目推进，进度一目了然，需要深度修改时一键切换回 IDE 模式。

TRAE 有一个“我的产物”页面（下图），各种项目产生的网页、幻灯片、文档、表格、视频、图片等，都可以在这个页面统一管理，不管是在本机还在云端。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100707.webp)

（4）**能力扩展接口**

提供各种能力扩展渠道，并能连接外部服务或数据。以 TRAE 的插件市场为例，可以加载技能、MCP 和外部接口。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100705.webp)

对于即时通讯软件，它提供“我的助理”功能，连接后只要“@Trae”，就能远程接入。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100706.webp)

另外，它还提供各种文档模板和自动化任务模板，直接套用即可。

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100708.webp)

![](https://cdn.beekka.com/blogimg/asset/202610/bg2026100709.webp)

## 七、总结

我现在看上去，传统的 IDE 应该是走到头了。随着 AI Coding 的发展，开发工具的代码色彩会越来越淡，开始向通用的任务管理工具转变。

用户群体也将大变。专业开发者依然可以用它开发提效，小团队和个人则用它完成“全链路开发”，以前的很多的“领域工具”都将被它替代：项目管理、设计、测试、运营、文档、PPT 等等。

更重要的是，许多普通人也会开始使用它，他们不懂代码，但懂业务和产品，希望开发出自己需要的工具，开发工具内置的 AI Agent 将帮助他们完成无码开发，做出 Demo。

## 介绍

文章可通过场景化开发流程演绎，自然带出双模式切换以及新增功能点。

1. 一端拥有Agent与IDE双模式，覆盖全链路开发每一环
Agent 模式是 TraeCode 新增的开发模式：它让你在一个窗口内管理所有项目、调度多个 Agent，把开发从「让一个 Agent 帮我写代码」，升级为「指挥多个 Agent 一起从想法开始到交付结果」。加上Agent模式后，TraeCode一共具有两个开发模式：
- Agent 模式：适合以 Agent 为中心的全局工作台，所有项目和 Agent 任务在统一工作台中调度，从需求到编码的一站式 Agent 协助。
- IDE 模式：保留之前双模式，其中SOLO 模式适合单项目的 AI 端到端辅助开发，IDE 模式则适合聚焦单项目的深度代码编辑。

2. 新增自动化、模板库、我的助理功能，让开发更加优质高效
围绕 Agent 模式，TraeCode 同步上线自动化、模板库和我的助理。自动化任务把重复流程交给 Agent 持续执行，比如定时整理进度、跑固定检查；模板库适合快速启动常见开发场景，让产品方案、页面搭建、数据分析、技术文档不必每次从零开始；我的助理则把文档、汇报、协同这些非编码环节接进来，让开发过程里的沟通和交付更加无损。

3. 文档、设计、代码等产物统一管理，开发全流程清晰可控
Agent 模式支持在同一个界面里管理多任务。Agent 生成的代码变更、HTML 报告、PPT、Word 文档、图片、视频等内容，都会统一进入「项目产物」。开发者不用再从聊天记录里翻结果，也不用担心产物散在不同地方；每一次调研、设计、编码和测试，都会沉淀成可回看、可展示、可继续交付的成果。

4. 桌面、网页端、移动端同步升级，开发随时随地
这次升级会覆盖桌面端、网页端和移动端，移动端也会去掉 Work / Code的模式区分，轻松开启任务下发。无论你是在电脑前推进项目，还是离开电脑后继续查看 Agent 任务进度，TraeCode 都会把多端任务、项目产物和开发流程接到同一个工作台里，让任务不因为设备切换而中断。

## IDE vs ADE

IDE指“集成开发环境”，由人提供动力，消耗头发与脑细胞，典型的有VSCode、IntelliJ IDEA、Neovim等。

Code Agent是指利用AI生成代码的工具，由大模型提供动力，消耗代币和电力，典型的有Claude Code、Codex、OpenCode等，下文简称为Agent。

ADE 指“Agent 驱动开发环境”，

IDE搭配AI对话框，就像在牛车马车上安装一个发动机，
