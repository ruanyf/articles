# 科技爱好者周刊（第 414 期）


## 如果人类文明停留在21世纪初

最近看到[一篇文章](https://lukaszkups.net/notes/early-2000s-were-peak-of-humanity/)，作者感叹，要是人类文明停留在21世纪初的水平，不再向前发展，那该多好。

具体来说，就是停留在2007年6月29日之前。那是 iPhone 诞生的日子。作者的意思是，如果人类没有进入智能手机时代，保持那一时刻的科技水平，就很完美。

> "我真心认为，21世纪初可能是人类最接近科技与生活完美平衡的时期。
>
> 我们拥有足够的技术来让我们的生活更轻松，但技术还不足以让人感到担心。"

那时，手机只有部分智能功能，可以打电话、发短信、玩小游戏，有一个很烂的摄像头，基本上就是这样了。

互联网早已存在，可以搜索信息、发送电子邮件、下载音乐、与人聊天。但它不在你的口袋里，让你每隔37秒就查看一次。

那时，技术只是一种工具，不是一种生活方式。

那时，世界依然还是实体的，音乐保存在 CD，电影保存在 DVD，必须通过播放器播放。拍照需要相机，跟人聊天需要打电话，想知道朋友在干嘛，就要去问他们，想认识某人，就要去见面。

科技主要起到的是辅助真实世界的作用，而不是建立虚拟世界，试图取代真实世界。

那时，互联网只是一个去处而已。你坐在电脑前上网，完成任务后，你就下网。你不会永远在线，不像现在，你会发现自己时时刻刻在线，在网上工作，一边吃饭一边看视频，一边走路一边网上的音乐，然后一边上网一边就睡着了。

如果你现在有十分钟什么事情都不做，你就会问自己：“哪里出了什么事情？”

那时有论坛，有网上聊天，你仍然可能会花费太多时间与网上的陌生人聊天。不同之处在于，互联网不是你全部的社交，你可以在网上消失三个月，没人指望你发布关于自己的最新动态，也没有算法来判断你这个人是否有趣。

那时，做什么事情都没有那么方便，你无法完全依靠互联网去完成，很多事情还是必须自己亲自去做。

后来我们不再问这个问题了：“技术如何让这一切变得更简单？”

而是开始问：“技术如何完成它？”

你想购物？你需要一款 App。

你需要地图？你需要一款 App。

你想约会？你需要一款 App。

你需要朋友？你需要一款 App。

你的回忆都变成了云存储，你的对话都变成了即时通话，你的注意力都被无限滚动消耗了。

我们不断地为那些原本运行良好的事物创建数字副本。

技术确实让我们的生活变得更便捷，但是也因为成为了我们生活的中心。

如今，你想要更多的生活，就只有更多参与数字化，再装更多的 App。

虽然科技让我们的生活变得更方便，提供更多可能性，我们回首才发现，曾经的生活是如此不同。虽然没有那么方便，但是在那时，我们也可以快乐地生活。

人类的最佳生活时期，会不会就在刚刚过去的21世纪初：足够现代化，足够便利，但又不是那么现代化，那么便利。你无需时刻接触科技，也能体验到科技带来的好处。生活的大部分没有被数字化，这也意味着很多事情你通过互联网做不到，不得不亲自去做。

虽然那时的生活还有很多糟糕的部分，比如网速很慢，还有 Flash 和 Internet Explorer。

我们会毫不犹豫选择更便捷、更科技的生活，但回过头却发现缓慢生活和不便利，也有让人怀念一面。

希望2007年开始的智能手机革命，2022年开始的 AI 革命，能把我们带到一个更好的地方。


## AI 会让所有的东西短缺吗？

https://out-of-hell.xylon.me.uk/shortage.html

AI 已经让内存、闪存、硬盘出现了短缺。在美国，燃气轮机和其他发电设备的成本，也翻了一翻。

工厂厂房被分配给 AI，比如汽车工厂开始改造成服务器工厂。

未来如果人形机器人开始大规模生产，那么我认为，短缺问题可能会蔓延到几乎设备。

假设现在全世界突然需要大量机器人，那么不转型生产机器人（或机器人零件）就太愚蠢了，利润率会高得多。

即使是那些继续生产汽车的公司，其零部件成本也会更高，因为它们将面临铜、铝、锂离子电池等原材料的竞争。

所以我预测，未来十年，几乎所有制成品的价格都会飙升。从汽车到微波炉再到洗衣机，无一例外。

以市值来看，全球市值最高的公司是英伟达（NVIDIA），市值达 5.5 万亿美元，该公司主要生产人工智能硬件。排名第二的是苹果公司，市值达 4.7 万亿美元，该公司主要生产面向人类的硬件。

我认为我们需要为这样一个世界做好准备：大部分经济活动都服务于人工智能，而人类在市场中所占的比例相对较小。

传统企业很可能代表人工智能的利益。一群超级智能人工智能控制着一家雇佣人类并操控众多机器的公司。

## 编程已经面目全非

大家讨论更多的是，AI 对程序员这个职业的冲击，但是 AI 对编程的改变却谈得不多。

实际上，AI 已经推翻了传统的软件开发方法论，以前那些做法难以为继了。即使 AI 泡沫可能破灭，但是 AI 已经永久成为编程工具链的一部分，再也无法改变了。

一个国外的资深程序员分享了自己的[预测](https://x.com/thorstenball/status/2101305394190557466)，传统的编程方法那些已经被冲击。他的观点非常激进，有些地方让你觉得居然已经到了这一步，我觉得一定要分享出来。

（1）代码审查（Code review）将消失。

实际上现在已经没意义了，因为人类无法在合理的时间内，发现 AI 生成的代码中的Bug。

在未来，人类只能由审查系统或架构组成，而绝不会是在PR（Pull Request）里逐行去审查代码。

（2）单元测试可能会消失。

因为代码里面的一个个单元，都是 AI 生成的，你没法自己写单元测试了，让 AI 为它随时可能改变的代码写单元测试，也意义不大。

在未来，你只可能自己写一些集成测试（Integration Test）和系统测试（System Test），去测试代码。

（3）软件开发的重点将会改变。

“写代码”不再是开发重点，程序员的工作重点将移到其他环节：如何用软件解决业务问题、了解软件是如何实现的、如何发布软件、如何收集反馈等等。

（4）Bug 的性质也变了。

大多数 Bug 不会是代码 Bug，而是“需求提错了”的 Bug。

（5）软件开源不再能提升质量。

以前，开源的一个理由是“只要关注的人足够多，所有 Bug 都能被发现”。这句话依然成立，但是你现在不开源，AI 也能帮你发现 Bug。

（6）敏捷编程会死亡。

敏捷编程的各种方法—— Agile、Scrum 等——都意义不大了，未来的做法就是把工单直接推给 AI。

（7）项目分工将改变。

以前，项目组一般会分成三种角色：项目经理（PM）、设计师（Designer）、工程人员（Engineer）。这种三元架构将消失。

（8）“好代码”的概念将消失。

“好代码”的概念主要基于“便于人类阅读理解，方便重构、开发维护效率较高的基础上。但人类已经不读代码、不直接修改和维护大部分代码，“好代码”的存在前提就消失了。

（9）代码风格规范和 linter 工具，也没意义了。

AI 还会在乎“每行不超过80个字符”或“有没有换行符，要不要缩进……这一类的问题吗。

（11）UI 将变得不重要。

一方面，未来的很多 UI 是给 AI 使用的，而 AI 只需要 API，不需要精致的UI。

另一方面，如果模型速度变得极快，那么用户界面（UI）将实时生成。许多 UI 之所以存在，是因为软件无法确定你想要什么。菜单、设置页、仪表盘、过滤器，都是为了帮助用户快速确定需求。如果用户通过语言明确了需求，AI 就是实时为他生成定制的 UI。

（10）Token 为王。

谁能够负担更多的 Token，谁的软件就更好。如果你没有足够的 Token，你就只能出第二梯队的软件。

## Markdown 正在变成源码

Markdown 格式[正在变成源码](https://htmx.org/essays/markdown-in-src/)，而不是文档。

它为提示词，应该和生成的源码一起，提交到`/src`目录。

Markdown 具有许多优秀的特性。

（1）它是纯文本，可以进行差异比较、搜索和审查。

（2）AI 可以像母语一样读写它。

（3）人类无需工具即可阅读和编辑它。

事实上，它已经作为 AGENTS.md 文件进入了源码。

1、[风力发电机的木质基座](https://www.bbc.com/news/science-environment-67718719)

为了获得更大的发电功率，风力发电机越造越大。

目前，风力发电机的基座都是圆柱形钢塔。随着它的直径和高度的增长，运输和架设难度快速上升。

![](https://cdn.beekka.com/blogimg/asset/202312/bg2023123009.jpeg)

一家瑞典公司最近推出了一个新方案：使用木板建造风力发电机的基座。

他们将多层木材粘合并压缩在一起，形成圆弧状。然后将这些部件带到工地，粘合成一个圆柱体，堆叠成塔。

![](https://cdn.beekka.com/blogimg/asset/202312/bg2023123010.webp)

这样的好处就是，基座的重量大大减轻，并且可以分块安装，使得运输和架设变得容易。

![](https://cdn.beekka.com/blogimg/asset/202312/bg2023123011.webp)

走进基座的内部，可以清晰地看到墙壁的木质纹理。

![](https://cdn.beekka.com/blogimg/asset/202312/bg2023123012.webp)

![](https://cdn.beekka.com/blogimg/asset/202312/bg2023123013.webp)

如果这种木板被证实，可以胜任风力发电机的基座，具有足够的强度，并且能够防火。那么，它就也可以用来建造高层建筑，具有广阔的前景。

1、[RSA 因数分解](https://saweis.net/posts/rsa-896.html)

RSA 是一种常用的密钥算法，它的可靠性完全取决于它的公钥能否被因数分解。

以前，RSA 密钥被分解的最高纪录是768位（二进制位）。9月20日，Anthropic 公司的一位软件工程师宣布，他在 Claude 的帮助下，分解了896位的 RSA 密钥。

下面就是他放出来的密钥，以及分解后的两个质因子。

![](https://cdn.beekka.com/blogimg/asset/202609/bg2026092002.webp)

据他[透露](https://nitter.netbub.com/sweis/status/2101484464807596264)，他用 Claude 模型将因数分解的软件库 CADO-NFS 移植到 GPU 运行，在2048个 GPU 上运行了10天，才得到结果。

既然个人已经可以破解这么长的密钥了，那么大机构可以破解多少位的密钥？所以，目前都建议，RSA 密钥最少也要2048位。

1、[石油盐穴](https://johnjwang.com/post/2026/09/15/engineering-behind-us-strategic-petroleum-reserve)

美国的很多石油，不储存在地面的油罐，而是储存在地下的盐穴。

![](https://cdn.beekka.com/blogimg/asset/202609/bg2026092006.webp)

这样做有很多好处。

（1）盐穴比油罐大得多，可以储存更多的石油，更节省土地。（2）盐穴不易发生泄漏和火灾。（3）盐穴的防攻击性好，敌人的攻击难度很大。（4）盐穴更便宜，美国能源部的估计是，盐穴的每桶储存成本是3.5美元，而地上油罐为15至18美元。

![](https://cdn.beekka.com/blogimg/asset/202609/bg2026092007.webp)

盐穴指的是地下的盐矿洞穴。具体做法是，工程师先在盐矿中打孔，然后注入淡水。盐会溶解在淡水中，导致盐穴变大。

然后，将水抽出，就可以注入石油了。由于盐的渗透性极低，流体无法穿过它，它也不会与石油发生化学反应，所以石油放在里面非常安全。

取出石油的时候，只需要再次向盐穴注入淡水就可以了。因为石油比水轻，所以会浮到上层，直接取出即可。

盐穴的问题是，每次抽取石油，注入的淡水会溶解更多的盐分，逐渐扩大盐洞，所以无法多次重复使用。

## 文摘

1、[为什么编号应该从零开始](https://www.cs.utexas.edu/~EWD/transcriptions/EWD08xx/EWD831.html)

作者：Edsger W. Dijkstra（著名计算机科学家）

有一个自然数序列，从2一直到12，我们可以写成 2, 3, ..., 12。

在程序中表达这个序列，我们不会使用三个点的省略号，而是用不等式，会有四种写法。

> - a） 2 ≤ i < 13
> - b） 1 < i ≤ 12
> - c） 2 ≤ i ≤12​​
> - d） 1 < i < 13

请问哪一种写法更好一些？

回答是 a 和 b 好于 c 和 d。理由是 a 和 b 的边界差异等于序列的长度。如果还有后续的序列，那么一个序列的上限等于另一个序列的下限。

a 和 b 里面，哪一个更好一点呢？

考虑到存在最小自然数，所以下限是可以封闭的，因此 a 是更好的写法，可以从最小自然数写起。

下一个问题是，当处理长度为 N 的序列时，我们希望通过下标区分其中的元素，起始元素应该分配什么下标值？

遵守 a 的写法，从下标 1 开始时，下标范围为 1 ≤  i  <  N +1；但是，从 0 开始，可以给出更精确的范围 0 ≤   i  <  N，上限正好等于长度。

因此，让序列编号从零开始，元素的序数（下标）等于它前面的元素数。
