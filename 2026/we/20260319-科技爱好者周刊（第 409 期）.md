## 程序员的职业未来

AI 编程出现后，社会上就有一种声音，认为程序员这个职业大概不行了，以后代码都是机器生成。

甚至有一些程序员，自己也很悲观，看不到发展前景。

![](https://cdn.beekka.com/blogimg/asset/202608/bg2026081502.webp)

那么，怎么看待这个问题，程序员作为一个职业，以后会怎样？

我最近看到一个老外的[分析](http://newsletter.powderworks.dev/p/tabs-spaces-hand-tools-and-seat-belts)，觉得比较靠谱。他不是纯粹的主观臆断，而是依据行业的内在逻辑，分析接下来最可能的发展。

他说，大家要记住，大多数的商业软件开发是一个工业流程，而非手工流程。**软件行业同样必须符合工业化的要求**：扩大产出，降低成本，提高产品可靠性和生产稳定性。

软件行业的内在动力，其实不是 AI，而是工业化。AI 恰巧能够满足工业化的要求，还是加速满足。

展望未来，大概有几点基本判断。

（1）大模型将越来越智能、速度越来越快、价格越来越便宜。

（2）编码代理（coding agent）会不断改进，越来越强大。

（3）AI 的估值泡沫或许会破裂，甚至可能引发混乱，但编码代理程序将长期存在，不会消失。它们已经以某种形式永，久地成为软件开发流程的一部分。

（4）公司管理层将继续向程序员施加巨大压力，要求程序员尽可能多地使用编码代理。公司希望降低软件开发的技能门槛，并增加程序员的工作强度。在公司眼里，如果市场部的销售人员也能开发软件，那就再好不过了。

（5）中小规模项目的语言和框架锁定现象正在逐渐消失，到2027年底将不复存在。AI 将选择它认为最合适的语言和框架。

（6）那些用 Zig、Clojure、Elixir 和 Haskell 等冷门语言编写的专业项目，如果缺乏真正充分的理由，将被淘汰，并让 AI 自动重写成更符合主流模式的语言，例如 Python、Ruby、TypeScript 和 Rust。

（7）编码代理的使用，以及手工编写代码，都将会受到越来越严格的限制。软件行业下一步的主要热点，将是量化代码的质量标准，并尽可能地实现高质量代码生产的自动化。

（8）软件开发进一步走向工业化，那些还想手动编程的程序员可以业余时间在家里搞，在工作中，行业标准将越来越倾向于让程序员尽可能多、尽可能频繁地完成工作。

（9）确保代码质量的自动化工具将会不断涌现，且越来越便宜、越来越好用。大多数软件都不应该通过手工或个人创作的方式完成，这样做在经济上也越来越不可行。

![](https://cdn.beekka.com/blogimg/asset/202312/bg2023123009.jpeg)

![](https://cdn.beekka.com/blogimg/asset/202312/bg2023123011.webp)

![](https://cdn.beekka.com/blogimg/asset/202312/bg2023123013.webp)

1、[工程师如何建造东西](https://adapt.com/blog/build-wide-ship-narrow)

优秀工程师会在开发之前做好规划：先写一份功能需求文档（RFC）来描述功能，然后将其拆分成更小的任务，再逐个开发。

编写任何一行代码之前，整个工作流程就已经确定了。

这个流程很合理，但它要求你在对问题了解最少的时候做出最关键的结构性决策。

在动手搭建任何东西之前，你都在猜测：哪些部件可以拆卸，每个部件的复杂程度如何。有时你的猜测是对的，但通常情况下，你的猜测是错的，前一步最终会被抛弃。

这种试错并不是白白付出代价：在搭建过程中，你可以学到东西，如果一开始你规划了一个错误的架构，然后动手实现这个错误的架构，这很可能让你学得更快。

1、[为什么编号应该从零开始](https://www.cs.utexas.edu/~EWD/transcriptions/EWD08xx/EWD831.html)

作者：Edsger W. Dijkstra（著名计算机科学家）

有一个自然数序列，从2一直到12，我们可以写成 2, 3, ..., 12。

在程序中表达这个序列，我们不会使用三个点的省略号，而是用不等式，会有四种写法。

> - a） 2 ≤ i < 13
> - b） 1 < i ≤ 12
> - c） 2 ≤ i ≤12​​
> - d） 1 < i < 13

请问哪一种写法更好一些？

回答是 a 和 b 好于 c 和 d。理由是 a 和 b 的边界差异等于序列的长度。如果还有后续的序列，那么一个序列的上限等于另一个序列的下限。

a 和 b 里面，哪一个更好一点呢？

考虑到存在最小自然数，所以下限是可以封闭的，因此 a 是更好的写法，可以从最小自然数写起。

下一个问题是，当处理长度为 N 的序列时，我们希望通过下标区分其中的元素，起始元素应该分配什么下标值？

遵守 a 的写法，从下标 1 开始时，下标范围为 1 ≤  i  <  N +1；但是，从 0 开始，可以给出更精确的范围 0 ≤   i  <  N，上限正好等于长度。

因此，让序列编号从零开始，元素的序数（下标）等于它前面的元素数。
